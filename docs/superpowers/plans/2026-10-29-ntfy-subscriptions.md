# ntfy 认证订阅与系统通知实现计划

**目标：** 持久化服务器、用户名、明文密码和单个主题；启动自动恢复订阅，收到消息显示列表及系统通知。

**架构：** React 负责配置和状态展示；Rust 负责配置读写、Basic Auth、ntfy JSON 流、重连和通知。连接取消必须先停止旧任务；仅 Rust 发起网络请求。应用关闭即停止，不实现托盘。

**技术栈：** 现有 Tauri 2 / React / TypeScript / pnpm；Rust reqwest、tokio、Tauri notification 插件。

## 已批准规格与约束
- 单服务器、单主题；用户名密码认证，不实现 Token。
- 应用配置目录中明文保存密码；Unix 文件权限 0600，目录 0700；不记录密码。
- HTTP 明确警告；HTTPS 使用系统证书校验；拒绝 URL 内嵌账号密码、查询和片段，禁止自动重定向以防认证信息外泄。
- 启动恢复配置并连接；允许保存并连接、断开、清除配置。
- 实时消息列表只保留本次运行最近 100 条；去重缓存有界；只提醒 message 事件，不提醒 open/keepalive。
- 网络错误自动重连，认证拒绝不无限重试；通知失败可见但不停止消息接收。
- 不支持附件、操作按钮、多主题或后台驻留。

## 文件职责
- `src-tauri/src/config.rs`：配置验证和限制权限的原子持久化，含单元测试。
- `src-tauri/src/subscription.rs`：JSON 分帧、ntfy 事件、请求、去重和重连，含本地 HTTP 测试。
- `src-tauri/src/lib.rs`：Tauri 命令、连接生命周期、状态快照与系统通知。
- `src/App.tsx` / `src/App.css`：配置表单、HTTP/明文提示、状态、消息列表。
- `src/App.test.tsx`：模拟 Tauri 边界验证恢复、连接、断开和错误展示。
- `README.md`：运行说明、安全约束及手工通知验收。

## 审查重点
- 错误凭据不泄漏、不重连风暴。
- 快速重复连接/断开后不能产生旧连接的通知。
- 服务器路径前缀和非法主题、URL 必须验证。
- 网络分片、重复消息、超长/损坏帧不能导致重复通知或内存无限增长。
- 配置写入失败保留旧配置；通知失败不能中断订阅。

## 验证备注
- 核对 ntfy 上游 `parseSince`：不支持 `since=now`；新增失败测试后改为首次不传 since，重连传最后消息 ID。
- rust-analyzer 探测仍报告 `!bool`、数组不能索引、Tauri 宏展开类型等异常；同一源码的真实 Rust 编译、测试和 Clippy 全通过。未修改机器的分析器配置，此编辑器诊断差异仍保留。
- 系统通知插件只能确认提交 / 准备阶段的可观测错误，无法保证操作系统实际展示；README 已明确通知权限、勿扰模式及桌面验收限制。
- 手动重新连接清空消息列表；自动网络重连保留列表。消息不落盘，离线补收依赖服务器缓存。
