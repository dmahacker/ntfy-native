# GitHub 自动更新与紧凑无边框窗口

## 已确认需求

- 启动后后台检查 GitHub 正式 Release；发现更新后提示，由用户确认下载安装并重启。保留手动检查入口。
- 草稿版本不提供更新；延用 tag 触发构建、构建成功后生成草稿的发行方式。
- Windows NSIS、macOS 两种架构、Linux AppImage 支持应用内升级。Linux deb/rpm 提示从 Release 下载新包，不尝试修改系统包管理器安装的文件。
- 无系统边框，提供可拖动标题栏和最小化、最大化/还原、关闭按钮。
- 关闭继续复用现有 Rust CloseRequested：托盘可用时隐藏，无托盘时退出。
- 连接设置在正常窗口大小下一屏完整显示；消息列表可内部滚动，窗口整体不滚动。
- 不改变连接、密码存储、通知、未读计数、声音和自启动语义。

## 实现决定

- 采用 Tauri 2 官方 updater 和 process 插件；签名校验由 updater 插件执行，禁止不安全 HTTP 更新源。
- 更新入口固定为本仓库公开 Releases 的 latest.json；私有仓库不内嵌 GitHub token。
- 更新状态放在 App 根级，切换消息/设置视图不重新检查。后台启动发现更新不主动弹出主窗口；用户打开窗口时可见提示。
- 手动确认后才开始下载。下载/安装状态防重复点击，失败可重试；安装完成后明确重启，重启失败保留可见提示。
- 默认窗口暂沿用 1040×760；采用左侧连接表单、右侧声音/自启动/更新设置的两列布局。根据实测确定最小窗口尺寸，目标不超过 960×680；不承诺在任意缩放或低于最小尺寸时仍一屏容纳所有内容。
- 长错误通过可展开详情显示，保持摘要和操作可见，不以裁剪隐藏错误。极端缩放/小工作区时允许局部区域滚动以确保可访问性，不让按钮不可达。
- 标题栏按钮使用明确中文无障碍名称；拖动区域不覆盖按钮，操作失败展示反馈。窗口关闭调用原生 close()，不直接退出进程。

## 发行与安全

- 在原有六个安装包之外生成 updater 所需的签名产物、.sig 和 latest.json；两种 macOS 架构均有明确平台条目。
- CI 使用 TAURI_SIGNING_PRIVATE_KEY / TAURI_SIGNING_PRIVATE_KEY_PASSWORD；私钥不入库、不出现在日志，公钥可以入库。
- 签名密钥需要安全生成和备份，由维护者确认后设置 GitHub Secrets。缺少签名配置时发布构建明确失败，不生成看似可更新的无效清单。
- updater 的签名不是 Apple 公证或 Windows Authenticode，现有系统安全警告仍可能出现。
- 先验证全部安装及更新资产齐全再生成草稿；不覆盖正式发布版本。正式发布草稿后客户端才收到更新。
- 不在本次开发中自动推 tag、公开 Release 或提升版本号；发布前另行同步版本和锁文件。
- 已安装 v0.1.0 无 updater，需要手动安装一次新的支持更新版本。

## 验收

- 前端单元测试覆盖更新状态机、窗口控制、切换视图不重复检查和现有行为回归。
- Rust 测试、格式、Clippy 通过；配置和工作流通过静态检查。
- 实际浏览器检查默认尺寸与最小尺寸的文档滚动高度、表单可见性、100 条消息内部滚动及长错误反馈。
- 原生桌面验收拖动/窗口按钮/托盘回退；跨平台 CI 验证全部产物；用两个不同版本的签名包验证真实更新。
- 未运行的跨平台安装和真实更新验收必须明确标记，不能以 mock 测试冒充。
